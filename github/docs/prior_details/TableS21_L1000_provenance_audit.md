Supplementary Table S21. Targeted audit of L1000 release/provenance reporting

Purpose and scope. This targeted audit evaluates the reporting granularity of data provenance in 12 directly relevant LINCS/L1000 perturbation-prediction, screening, or benchmark studies. It is not a systematic review and is not intended to estimate an unbiased field-wide prevalence. The sample prioritizes models directly adjacent to the manuscript’s cross-predictor analyses and recent methods that use similar L1000 workflows. Public article and linked-artifact evidence was re-checked on 25 September 2026.

Coding rules. “Traceable source” requires a GEO accession, named source/version, or an explicit public dataset repository. “Processing level” is counted only when an L1000 level (for example level 3 or level 5) is explicitly stated in the study article or directly linked study material; a level inferred only from another paper is not counted. “Named release/version” requires a release/version label beyond a generic L1000 name or GEO phase/accession (for example CMap LINCS Resource 2020 or CMap-L1000v1). The Bayesian peak-deconvolution dataset is treated here as a processing/data variant rather than an official release label. “Exact level-5 build” asks whether a build identifier at the granularity relevant to the main manuscript (for example level5beta2020 versus dcic2021) is reported. Public artifacts were checked in the paper and, where available, the authors’ linked repository or data deposit.

Audit summary. In the checked public materials, all 12/12 studies provided at least a broad traceable source through a GEO accession, named data source/version, or explicit public dataset repository. Eight of 12 explicitly stated an L1000 processing level, and 3/12 used a named release/version label beyond a generic L1000 name or GEO accession/phase. None of the 12 reported a level-5 build identifier at the granularity of level5beta2020 versus dcic2021. Many recent studies nevertheless provide processed data, code, or model artifacts, indicating that reproducibility infrastructure can be strong even when upstream release/build provenance remains coarsely specified.

Interpretation. The re-check strengthens a narrower conclusion rather than a claim of generally poor provenance reporting: broad source traceability was present in all audited studies, and processing level was often reported. However, source identity, processing level, named release, and exact processed build are distinct provenance layers. A GEO accession, CMap release name, or downloadable processed cache can locate or reproduce a study while still being insufficient to determine which level-5 build underlies a reported benchmark or ranking when multiple processed builds coexist.

Limitations. The sample is purposefully targeted and includes information from linked repositories where appropriate; it should not be used to estimate a field-wide reporting rate. Repository contents can evolve after publication, which is why the evidence was re-checked on a fixed audit date. This audit records what is explicitly recoverable from public materials and does not infer undocumented build identity from file contents. A formal systematic review would require a predefined search strategy, date cut-off, duplicate screening, independent coding, and archived snapshots of all evidence pages.
